# 数据可见性说明

> 本文档整理各业务模块中基于 `User.permission` 的数据可见性规则。
>
> 代码依据：`QjsqServiceImpl.java`、`QjsqController.java`、`QjsqMapper.xml`、`UserServiceImpl.java`、`XtrwServiceImpl.java`、`UserController.java`。

---

## 1. User.permission 角色定义

| 值 | Java 类型 | 业务含义 | 代码出处 |
|----|-----------|----------|----------|
| `1` | `long` | **管理员/经理** — 拥有全局数据可见性和审批权限 | `UserController.login()` L53: `user1.getPermission()==1` → 返回 `isAdmin:true`；`QjsqServiceImpl` L39: `user.getPermission()==1` → 返回全部请假记录 |
| `3` | `long` | **普通员工** — 仅可见自己的数据 | `UserMapper.xml` 中硬编码 `WHERE permission=3` 用于过滤非管理员列表 |
| 其他 | `long` | 未定义（代码中无明确处理） | — |

> **注意**：`User.permission` 的 Java 类型是 `long`，但实际业务值只有 1 和 3。
> `UserController.login()` 中存在一个**命名 bug**：`permission==1` 时返回的 JSON 中 `isAdmin` 写成了 `false`（L54），实际语义应为 `true`。前端不应依赖该字段的字面值，而应直接判断 `permission === 1`。

## 2. 请假模块（QjsqServiceImpl）的 permission 分支

### 2.1 核心代码

```java
// QjsqServiceImpl.getQjList()
public List<Qjsq> getQjList(Qjsq qjsq) {
    User u = new User();
    u.setUserId(qjsq.getUserId());
    User user = userMapper.getUser(u);
    if (user.getPermission() == 1) {       // ← 管理员分支
        Qjsq q = new Qjsq();               // ← 创建空条件对象（不带 userId）
        return qjsqMapper.getQjList(q);     // ← 查全部记录
    }
    return qjsqMapper.getQjList(qjsq);      // ← 非管理员：只查自己的
}
```

### 2.2 SQL 层面的动态条件

```xml
<select id="getQjList" resultType="Qjsq">
    SELECT q.*, u.userName FROM qjsq q, user u WHERE q.userId = u.userId
    <if test="userId != null and userId != ''">
        AND u.userId = #{userId}
    </if>
    ORDER BY ksTime
</select>
```

- 当传入的 `Qjsq.userId` 为 null 时 → **不加 userId 过滤** → 返回全部记录
- 当传入的 `Qjsq.userId` 有值时 → **按 userId 过滤** → 只返回该用户的记录

### 2.3 权限分支汇总

| 场景 | permission | QjsqMapper 收到的参数 | 返回数据 |
|------|------------|----------------------|----------|
| 管理员查看请假列表 | `== 1` | `Qjsq{userId=null}` → 无条件过滤 | **全部员工的请假记录** |
| 普通员工查看请假列表 | `!= 1` | `Qjsq{userId=当前用户ID}` → `WHERE u.userId=?` | **仅自己的请假记录** |

### 2.4 请假状态流转（qjzt 字段）

请假状态 `qjzt` 是 **String 类型**（非 int），由代码硬编码：

| 值 | 写入位置 | 说明 |
|----|----------|------|
| `"审批中"` | `QjsqMapper.xml` `addQjsq` INSERT 中硬编码 | 提交申请时的初始状态 |
| 自定义值 | `agreeQj` UPDATE `SET qjzt=#{qjzt}` | 由前端传入，如 `"已批准"` / `"已拒绝"` |

### 2.5 请假原因映射（qjyy 字段）

请假原因 `qjyy` 在 Controller 层做映射：

| 前端传值 | 映射后存入 DB | 代码位置 |
|----------|-------------|----------|
| `"0"` | `"事假"` | `QjsqController.addQj()` L40: `"0".equals(qjsq.getQjyy()) ? "事假" : "病假"` |
| 任何非 `"0"` 的字符串 | `"病假"` | 同上 |

> **注意**：此映射只支持两种假期类型（事假/病假），且 `"0"` 是 magic string。前端传 `"1"` / `"sick"` / `"abc"` 都会被映射为病假。

## 3. 各模块数据可见性全景矩阵

| 模块 | 接口 | 管理员 (permission=1) | 普通员工 (permission=3) | 鉴权方式 |
|------|------|:---:|:---:|------|
| **请假列表** | `GET /qjsq/getQjList` | 全部记录 | 仅自己 | Service 层 `permission==1` 判断 |
| **请假申请** | `GET /qjsq/addQjsq` | ✓ | ✓ | 无限制 |
| **请假审批** | `GET /qjsq/agreeQj` | ✓ (逻辑上) | ✓ (无代码拦截) | **无鉴权**，任何登录用户可调用 |
| **用户列表** | `POST /user/userList` | 全部用户 | 全部用户 | 无限制 |
| **打卡记录** | `POST /user/getDkList` | 取决于前端传参 | 取决于前端传参 | 无后端鉴权 |
| **会议室列表** | `POST /user/getHysList` | 全部 | 全部 | 无限制 |
| **会议预约** | `POST /user/kh` | ✓ | ✓ | 无限制 |
| **协同任务详情** | `POST /xtrw/xtrwDetail` | 全部 | 全部 | 无鉴权，知道 xtrwId 即可 |
| **我负责的任务** | `POST /xtrw/myOwned` | 仅自己的 | 仅自己的 | SQL `WHERE zfrUserId=?` |

| **已完成任务** | `POST /xtrw/completed` | 全部 | 全部 | 无鉴权 |
| **部门可见任务** | `POST /xtrw/visibleTasks` | 按部门 | 按部门 | 无鉴权，知道 departmentId 即可 |
| **待办提醒** | `POST /xtrw/todoList` | 仅自己的 | 仅自己的 | SQL `WHERE userId=?` |

## 4. 已知的可见性安全隐患

### 4.1 请假审批无鉴权

`agreeQj` 接口没有校验调用者是否为管理员。任何登录用户只要知道 `qjId` 就可以批准/拒绝任何人的请假申请。

```java
// QjsqController.agreeQj() — 无权限检查
public JSONObject agreeQj(Qjsq qjsq) {
    qjsqService.agreeQj(qjsq);  // 直接执行，无 permission 校验
}
```

### 4.2 请假列表 userId 可伪造

`getQjList` 接收前端传入的 `userId` 参数。普通员工如果篡改请求中的 `userId` 为空或其他值，可能绕过 `WHERE u.userId=?` 过滤，看到其他人的记录。

```java
// QjsqServiceImpl.getQjList() — 信任前端传入的 userId
public List<Qjsq> getQjList(Qjsq qjsq) {
    // qjsq.userId 来自前端参数，没有从 session/token 中获取
    User user = userMapper.getUser(u);
    if (user.getPermission() == 1) { ... }
}
```

### 4.3 协同任务全局可见

Xtrw 模块的任务详情、逾期列表、已完成列表均不做权限校验。虽然设计上是"协同"场景，但敏感任务内容可能对不应看到的人暴露。

### 4.4 login 返回 isAdmin 字段 bug

```java
// UserController.login() L53-57
if (user1 != null && user1.getPermission() == 1) {
    return JSON.parseObject("{statusCode:200,user:{isAdmin:false,...}}");
    //                                              ^^^^^^^^^^^^^^
    //                                              应为 isAdmin:true
}
```

管理员登录时返回的 `isAdmin` 值为 `false`，与 `permission==1` 的实际语义矛盾。前端若依赖 `isAdmin` 字段做权限判断将产生错误行为。应使用 `permission` 字段判断。

## 5. Magic Number / Magic String 汇总

| 模块 | 字段 | 值 | 业务含义 | 代码位置 |
|------|------|----|----------|----------|
| User | `permission` | `1` | 管理员/经理 | `QjsqServiceImpl` L39, `UserController` L53 |
| User | `permission` | `3` | 普通员工 | `UserMapper.xml` WHERE 过滤 |
| Qjsq | `qjyy` (入参) | `"0"` | 事假 | `QjsqController` L40 |
| Qjsq | `qjyy` (入参) | 非 `"0"` | 病假 | `QjsqController` L40 |
| Qjsq | `qjzt` (DB) | `"审批中"` | 初始状态 | `QjsqMapper.xml` INSERT 硬编码 |
| User login | `statusCode` | `200` | 登录成功 | `UserController` L54/59 |
| User login | `statusCode` | `404` | 登录失败（用户不存在或密码错误） | `UserController` L64 |
| User login | `isAdmin` | `false` | **Bug**：permission=1 时应为 true | `UserController` L54 |
