# 数据可见性说明

> 本文档从 `QjsqServiceImpl`、`QjsqMapper.xml`、`QjsqController`、前端 `Form.vue` 及 `api.js` 反推，说明请假申请模块的数据可见性与权限控制规则。

---

## 1. 权限模型

系统使用 `user.permission` 字段（INT 类型）区分角色，没有独立的角色表。

### 1.1 permission 值字典

| 值 | 角色 | 对应职位（zw） | 数据可见范围 | 代码依据 |
|---|---|---|---|---|
| **1** | 管理员 / 经理 | 经理 | 看到**所有人**的请假记录 | `QjsqServiceImpl.java:39` |
| **3** | 普通员工 | 员工 | 仅看到**自己**的请假记录 | `QjsqServiceImpl.java:43` |

> **注意**：值 `2` 在当前代码中未使用。`UserMapper.xml:27` 中 `getUserList` 的查询条件硬编码了 `WHERE permission=3`，即仅筛选普通员工。

### 1.2 权限如何传递到前端

```
登录 → UserController.login() → 返回 JSON 含 permission 字段
                                          │
                                          ▼
                              前端存入 sessionStorage
                                          │
                                          ▼
                          各页面读取并比较 permission == '1'
                                   是 → ifAdmin = true
                                   否 → ifAdmin = false
```

代码位置：`UserController.java:51-65`。注意登录响应中 `isAdmin` 字段被硬编码为 `false`（对所有角色），前端实际忽略此字段，完全依赖 `permission` 值判断。

## 2. 请假列表可见性核心逻辑

### 2.1 服务层分支（QjsqServiceImpl.java:35-44）

```java
public List<Qjsq> getQjList(Qjsq qjsq) {
    User u = new User();
    u.setUserId(qjsq.getUserId());
    User user = userMapper.getUser(u);        // 查询当前用户完整信息
    if (user.getPermission() == 1) {          // ★ permission == 1 → 管理员
        Qjsq q = new Qjsq();                 // 创建空查询对象（userId 为 int 默认值 0）
        return qjsqMapper.getQjList(q);       // → 返回全部记录
    }
    return qjsqMapper.getQjList(qjsq);       // → 返回仅该用户的记录
}
```

### 2.2 SQL 层条件过滤（QjsqMapper.xml:12-18）

```xml
<select id="getQjList" resultType="com.zjw.oa.entity.Qjsq"
        parameterType="com.zjw.oa.entity.Qjsq">
    SELECT q.*, u.userName
    FROM qjsq q, user u
    WHERE q.userId = u.userId
    <if test="userId != null and userId != ''">
        AND u.userId = #{userId}
    </if>
    ORDER BY ksTime
</select>
```

**MyBatis 动态条件行为**：当 `userId` 为 `int` 类型默认值 `0` 时，MyBatis 的 `userId != ''` 判断对整数 `0` 视为"空"（OGNL 规则），因此 `<if>` 条件**不生效**，返回全部记录。

### 2.3 可见性决策流程图

```
前端发送 getQjList(userId=当前登录用户ID)
         │
         ▼
    QjsqServiceImpl.getQjList()
         │
         ├─ 查询 user.permission
         │
         ├─ permission == 1 ?
         │      │
         │      ├─ YES (管理员)
         │      │      │
         │      │      ▼
         │      │   构造空 Qjsq (userId=0)
         │      │      │
         │      │      ▼
         │      │   SQL: SELECT q.*, u.userName
         │      │        FROM qjsq q, user u
         │      │        WHERE q.userId = u.userId
         │      │        ORDER BY ksTime
         │      │      │
         │      │      ▼
         │      │   返回 ★ 所有人的请假记录
         │      │
         │      └─ NO (普通员工)
         │             │
         │             ▼
         │          原始 Qjsq (userId=真实ID)
         │             │
         │             ▼
         │          SQL: SELECT q.*, u.userName
         │               FROM qjsq q, user u
         │               WHERE q.userId = u.userId
         │                 AND u.userId = #{userId}
         │               ORDER BY ksTime
         │             │
         │             ▼
         │          返回 ★ 仅自己的请假记录
         │
         ▼
    返回给前端
```

## 3. 前端 UI 可见性控制

前端 `Form.vue` 根据 `ifAdmin` 控制两组 UI 元素的显隐：

### 3.1 申请按钮 — 仅员工可见

```html
<!-- Form.vue:5 -->
<el-button v-if="!ifAdmin" type="primary" @click="apply">请假申请</el-button>
```

| 角色 | 按钮可见 | 说明 |
|------|:-------:|------|
| 管理员 (permission=1) | 隐藏 | 经理不通过此页面提交请假 |
| 员工 (permission=3) | **显示** | 员工可发起请假申请 |

### 3.2 审批操作列 — 仅管理员可见

```html
<!-- Form.vue:15-19 -->
<el-table-column label="操作" v-if="ifAdmin">
    <el-button @click="handleAgree(scope.row, 1)">同意</el-button>
    <el-button @click="handleAgree(scope.row, 0)">拒绝</el-button>
</el-table-column>
```

| 角色 | 操作列可见 | 说明 |
|------|:--------:|------|
| 管理员 (permission=1) | **显示** | 可审批所有请假 |
| 员工 (permission=3) | 隐藏 | 无审批权限 |

### 3.3 审批按钮禁用规则

```javascript
// Form.vue:109-113
buttonAble(row) {
    if (row.qjzt == '审批中') return false;  // 按钮可用
    else return true;                         // 按钮禁用（已处理）
}
```

已审批（`同意`/`拒绝`）的记录，按钮置灰不可操作。

## 4. 请假状态（qjzt）值字典

| 值 | 含义 | 设置位置 | 说明 |
|---|---|---|---|
| `'审批中'` | 待审批 | `QjsqMapper.xml:9` — INSERT 硬编码 | 前端也传此值但被 SQL 覆盖 |
| `'同意'` | 已批准 | 前端 `Form.vue:81` → `/qjsq/agreeQj` | 管理员操作 |
| `'拒绝'` | 已驳回 | 前端 `Form.vue:86` → `/qjsq/agreeQj` | 管理员操作 |

状态流转：

```
   申请提交          管理员审批
      │                │
      ▼                ├─── 同意 ──→ qjzt = '同意'
  qjzt = '审批中' ────┤
                       └─── 拒绝 ──→ qjzt = '拒绝'
```

## 5. 请假类型（qjyy）值字典

| 前端发送值 | 后端存储值 | 含义 |
|-----------|-----------|------|
| `"0"` | `事假` | 事假（个人事务） |
| 非 `"0"` | `病假` | 病假 |

**转换逻辑**（`QjsqController.java:40`）：

```java
qjsq.setQjyy("0".equals(qjsq.getQjyy()) ? "事假" : "病假");
```

> **已知问题**：前端下拉框直接发送中文值 `"事假"` / `"病假"`（`Form.vue:29-31`），而后端期望 `"0"` 表示事假。由于 `"事假" != "0"`，事假会被后端错误转换为 `病假`。

## 6. 接口与权限对照表

| 接口路径 | 用途 | 服务端鉴权 | 前端鉴权 | 安全风险 |
|---------|------|:--------:|:-------:|---------|
| `GET /qjsq/getQjList` | 请假列表 | **有**（按 permission 过滤） | userId 从 sessionStorage 取 | userId 可伪造 |
| `GET /qjsq/addQjsq` | 提交申请 | **无** | 仅员工看到按钮 | 任何人可构造请求 |
| `GET /qjsq/getQjXx` | 请假详情 | **无** | 无 | 传任意 qjId 可查看任意记录 |
| `GET /qjsq/agreeQj` | 审批操作 | **无** | 仅管理员看到按钮 | 任何人可构造请求审批 |

### 安全说明

1. **数据过滤仅在 `getQjList` 生效**：这是唯一进行服务端权限判断的接口。
2. **`agreeQj` 无鉴权**：后端不验证调用者是否为管理员（permission=1）。安全性完全依赖前端隐藏按钮，可被绕过。
3. **`getQjXx` 无鉴权**：任何知道 `qjId` 的用户可查看他人请假详情。
4. **GET 用于写操作**：`addQjsq` 和 `agreeQj` 使用 HTTP GET（`api.js:31,33`），状态变更操作应使用 POST。
5. **userId 客户端传入**：`getQjList` 的 `userId` 来自前端 `sessionStorage`，后端直接信任，未校验登录态。

## 7. 全系统 permission 值使用汇总

`permission` 检查不仅出现在请假模块，在以下前端页面中均有相同的判断模式：

```javascript
// 所有页面统一写法
user.permission == '1' ? this.ifAdmin = true : this.ifAdmin = false
```

| 文件 | 行号 | ifAdmin 控制的内容 |
|------|------|-------------------|
| `Form.vue` (请假) | 100 | 申请按钮（员工可见）、审批列（管理员可见） |
| `user.vue` (会议室) | 228 | 通知按钮、会议室状态编辑 |
| `Table.vue` (任务) | 342 | 管理员操作列 |
| `Page4.vue` | 143 | 管理员专属功能区 |
| `information.vue` | 67 | 信息编辑权限 |

> **一致性说明**：前端使用 **字符串** 比较 `=='1'`，后端使用 **整数** 比较 `==1`。由于 JavaScript 的 `==` 宽松比较，`1 == '1'` 为 `true`，因此在当前实现中不会出问题。但如果切换为 `===` 严格比较，当后端返回数字 `1` 时前端判断将失败。
